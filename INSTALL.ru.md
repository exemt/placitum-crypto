# Установка

[English](INSTALL.md) · Русский

Сервис ставят рядом с контроллером: он нужен, только когда сертификаты и ключи загружают через
панель. Обычно его ставит `placitum-core`; здесь — что ему нужно и как проверить, что он работает.

## Что нужно рядом

| Компонент | Обязателен | Зачем |
| --- | --- | --- |
| Контроллер | да | у него сервис забирает ciphertext объекта и ему же отвечает метаданными |
| Приватный ключ установки | да | им открываются конверты; файлом, не переменной |
| NATS | нет | только ради собственного журнала и живого уровня |

Своей базы, тома и состояния у сервиса нет: перезапуск ничего не теряет.

## Настройки

| Переменная | По умолчанию | Что задаёт |
| --- | --- | --- |
| `WAF_CRYPTO_HTTP` | `:8093` | адрес HTTP API |
| `WAF_NODE_KEY` | пусто | путь к приватному ключу установки (PKCS#8 PEM). Без него сервис стартует, но запросы метаданных получают `503 key_unavailable`; ключ, который не читается, не даёт стартовать |
| `WAF_CONTROLLER_URL` | — | обязателен; откуда забирать ciphertext, например `http://controller:8080` |
| `WAF_NATS_URL` | пусто | шина для журнала; без неё журнал остаётся в stdout |
| `WAF_CRYPTO_LOG` | `info` | уровень журнала |
| `WAF_CRYPTO_REQUEST_TIMEOUT` | `5s` | потолок запроса к контроллеру |

Ключ монтируется файлом с правами на чтение только процессу: окружение видно соседям по машине и
уходит в дампы, файл — нет.

## Docker Compose

```yaml
services:
  crypto:
    image: placitum/crypto
    environment:
      WAF_CRYPTO_HTTP: ":8093"
      WAF_NODE_KEY: /run/secrets/waf_node_key
      WAF_CONTROLLER_URL: http://controller:8080
      WAF_NATS_URL: nats://nats:4222
    secrets: [waf_node_key]

secrets:
  waf_node_key:
    file: ./secrets/contour.key
```

`:8093` наружу не публикуют: в сервис ходит контроллер, а не браузер.

## Проверка

```sh
curl -fsS http://127.0.0.1:8093/healthz
```

Дальше — из панели: загрузите сертификат с ключом и откройте его карточку. Если в ней видны SAN и
срок, а контроллер не жалуется, цепочка панель → контроллер → crypto → метаданные работает.

`undecryptable` при верном ключе означает, что формат конверта у шифратора панели и у этого
читателя разошёлся. Конверт пишут в нескольких местах, чинить надо все реализации разом.

## Типичные ошибки

- **Ключ установки один на установку.** Тот же файл получают агенты узлов, публичную половину —
  контроллер. Перевыпуск ключа делает нечитаемыми все ранее загруженные секреты.
- **Сервис не участвует в раскатке nginx.** Он держит тот же ключ, что агент, но конфигурацию не
  применяет и на узлы не ходит.
- **Открытый текст не возвращается никогда** — ни контроллеру, ни в журнал.
