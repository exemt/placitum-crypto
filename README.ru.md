# Placitum crypto

[English](README.md) · Русский

Процесс, который держит приватный ключ установки, рядом с контроллером. По запросу контроллера он
открывает конверт объекта хранилища — сертификата, приватного ключа, цепочки или списка отзыва — и
возвращает его метаданные; открытый текст остаётся внутри этого процесса.

Контроллер не должен видеть открытый текст секретов, которые оператор загрузил через панель. Но
показать оператору SAN и срок сертификата и проверить, что ключ ему соответствует, всё-таки нужно.
Для этого нужен приватный ключ, поэтому проверка идёт здесь.

```
панель ──► контроллер ──► crypto ── сам забирает ciphertext у контроллера
                             │      (GET /api/<scope>/store/<uuid>/blob)
                             └──►   метаданные: SAN, срок, соответствие ключа
```

Контроллер передаёт сюда только scope и UUID объектов.

## Сборка и запуск

```sh
docker build -t placitum/crypto .
docker run --rm -p 8093:8093 \
  -v /path/contour.key:/run/secrets/waf_node_key:ro \
  -e WAF_NODE_KEY=/run/secrets/waf_node_key \
  -e WAF_CONTROLLER_URL=http://controller:8080 \
  placitum/crypto
```

Что нужно рядом и все настройки — в [INSTALL.ru.md](INSTALL.ru.md).

## API

| Запрос | Ответ |
| --- | --- |
| `POST /v1/certificates/metadata`: `scope`, `cert_store_id`, необязательные `key_store_id` и `chain_store_id` | `sans`, `not_before`, `not_after`, `fingerprint`, `subject`, `issuer`, `serial`, `is_ca` |
| `POST /v1/crl/metadata`: `scope`, `crl_store_id` | `issuer`, `this_update`, `next_update`, `revoked` (число) |
| `GET /healthz` | `200`; ключ не проверяется |

У доверенного корня mTLS нет `key_store_id`: приватной половины нет, сверять нечего. `is_ca` берётся
из BasicConstraints самого сертификата, и по нему контроллер отклоняет листовой сертификат,
загруженный как корень.

Ошибки приходят JSON с кодом `error`:

| Статус | `error` | Когда |
| --- | --- | --- |
| `400` | `invalid_json`, `invalid_uuid` | тело не JSON или идентификатор не UUID |
| `404` | `store_object_not_found` | у контроллера нет такого объекта |
| `422` | `undecryptable` | конверт не открылся текущим ключом |
| `422` | `invalid_certificate`, `invalid_crl` | после расшифровки не сертификат или не список отзыва |
| `422` | `key_mismatch` | ключ не соответствует сертификату |
| `502` | `controller_unreachable` | не достучались до контроллера |
| `503` | `key_unavailable` | процесс запущен без ключа |

## Ключи и конверт

Ключ установки тот же, что у агентов узлов: приватная половина, файлом, с правами на чтение только
процессу; публичную держит контроллер. Конверт у всех, кто его пишет и читает, одного формата: версия,
длина обёрнутого ключа big-endian, RSA-OAEP-SHA256, дальше AES-256-GCM. Своей базы и состояния у
процесса нет, перезапуск ничего не теряет. Цепочка против системного доверия и подпись списка отзыва
здесь не проверяются; издателя списка с корнем сверяет контроллер.
